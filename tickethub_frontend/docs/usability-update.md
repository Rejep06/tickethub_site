# Tickethub — изображения, карта мест и интерфейс

Обновление от 7 октября 2026 года для версии `tickethub_frontend_backend_update.zip`.
В архиве изменён только frontend и его шаблон Nginx. Зависимости и `package.json` не менялись.

## Установка в существующий проект (Windows / PowerShell)

Остановите `npm run dev` сочетанием Ctrl+C и сделайте копию папки проекта. Из patch-архива скопируйте **содержимое** `tickethub_frontend` поверх существующей папки, подтвердив замену. Не создавайте вторую вложенную папку с тем же именем.

Сохраните свои `.env.local`, `package-lock.json` и `node_modules`: в обновление они не входят. Самостоятельные изменения исходников предварительно сравните с patch.

В папке frontend:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev
```

Для уже установленного проекта повторная установка пакетов не нужна. Полный архив подходит для новой папки: скопируйте туда свой `.env.local` и выполните `npm install --include=optional` на компьютере с доступом к npm. Настоящий lock-файл должен создать npm — он не подменён вручную.

Нужен backend с новыми лимитами изображений, SVG и полем `image_url`, описанными в вашем последнем сообщении. Старый архив backend `portalbilet_editor_partial` предшествует этому контракту.

## Изображения

**Сотрудники → Мероприятия → мероприятие → Обложка**. Для схемы: **Схемы → черновик → Фоновое изображение**. При создании мероприятия можно сразу задать обложку.

В форме два взаимоисключающих способа: **С устройства** и **По ссылке**.

| Проверка | Ограничение |
|---|---|
| PNG / JPEG / WebP | 100 МиБ, то есть 104 857 600 байт |
| Статический SVG | 10 МиБ, то есть 10 485 760 байт |
| Каждая сторона | Не больше 20 000 px |
| Площадь | Не больше 300 000 000 px |

20 000 × 15 000 разрешено, 20 000 × 20 000 — нет. Браузер не уменьшает файл и не меняет его прозрачность. Для растра размеры читаются из заголовков PNG/JPEG/WebP, без распаковки всех пикселей. Необычные или повреждённые форматы окончательно проверяет backend.

SVG до серверной очистки не отображается в браузере. Большие растровые файлы тоже не декодируются для локального предпросмотра: вместо него показываются имя и параметры файла. Это не отказ в загрузке. Небольшой растр получает обычный предпросмотр. Сохранённые изображения отображаются через `img` / Next Image в режиме `unoptimized`, без вставки XML в HTML.

По ссылке отправляется JSON; файл отправляется multipart. Сам frontend по введённой внешней ссылке ничего не скачивает и не пытается показать её до сохранения. Скачивание, проверка адресов/перенаправлений, ограничения и очистка SVG остаются задачей backend. `https://localhost`, приватные адреса и недопустимые SVG должны отклоняться сервером независимо от браузерных проверок.

`rights_source`, `rights_confirmed` и `expected_version` сохранены. При конфликте версии выбор файла/ссылки остаётся в форме; автоматической перезаписи нет. Опубликованная схема по-прежнему неизменяема — для замены фона нужна копия.

## Загрузка больших файлов через прокси

В `infra/nginx.conf.template` выставлены `client_max_body_size 110m` (запас к 100 МиБ для multipart) и `proxy_read_timeout 310s`. Это **шаблон**, а не изменение вашего работающего Nginx: перенесите соответствующие настройки в действующий конфиг и проверьте его перед перезагрузкой.

У загрузки изображения клиентский тайм-аут — 5 минут; у остальных API-запросов стандартные 25 секунд сохранены. POST не повторяется автоматически после обрыва. После неоднозначного тайм-аута сначала обновите карточку и проверьте изображение/версию.

В development `next.config.ts` дополнительно задаёт `experimental.proxyClientMaxBodySize: 110 * 1024 * 1024`. Эта настройка экспериментальная и относится к буферизации Next Proxy, а не ко всем возможным ограничениям инфраструктуры. Локализующий Proxy исключает `/api`; в production `/api/` направляется Nginx непосредственно в Django. Лимиты CDN/ingress, тайм-аут Django/Gunicorn и память обработчика проверяются отдельно. Изменение одной frontend-константы не гарантирует успешную загрузку 100 МиБ на любом сервере.

## Карта мест

Начальный вид — вся схема, мелкие маркеры без номеров. Фон и места перемещаются одной камерой, а не увеличением ширины страницы.

- Кнопки «+», «−» и «Вся схема», масштаб относительно общего вида.
- Колесо масштабирует область под курсором после активации карты; Ctrl/⌘ + колесо тоже активирует карту. До активации колесо прокручивает страницу.
- Перетаскивание для перемещения. На телефоне сначала нажмите «Управлять схемой», затем двигайте одним пальцем и увеличивайте двумя. Кнопка выхода возвращает обычную прокрутку.
- Выбор сектора или ряда приближает соответствующую область. Подписи секторов на общем виде кликабельны.
- В плотной области нажатие сначала приближает места. Номера появляются, когда между маркерами достаточно места.
- В приближении нажатие открывает карточку «сектор / ряд / место / цена» с кнопкой выбора. Недоступное место нельзя добавить, старый выбор можно убрать.
- При перетаскивании или pinch место не выбирается случайно.
- «Список мест» остаётся полноценным способом выбора с клавиатуры. Есть сектор, ряд, фильтр цены и страницы по 80 мест.

Вместо тысяч крупных DOM-кружков используется Canvas, пространственная сетка для поиска ближайшего места и отсечение точек вне экрана. Размер точки ограничен расстоянием до соседей. Невидимые зоны клика не перекрывают друг друга произвольным порядком: выбирается ближайший центр, включая недоступные места.

Координаты, цены и наличие не выдумываются. Если два разных места имеют **одинаковые x/y**, увеличение не исправит геометрию: интерфейс предложит список. При необходимости такие данные исправляют в редакторе/импорте. Проверка наличия и цены перед оформлением остаётся за backend.

## Вход, ошибки и внешний вид

`/ru/request` и `/en/request` показывают форму гостю. Вход по email-коду открывается перед отправкой внутри модального окна. Поля заявки остаются в памяти текущей страницы, код и контакты не записываются в localStorage. После входа заявка **не отправляется автоматически**: пользователь проверяет контакты и подтверждает её.

Отсутствие сессии теперь не изображается красной технической ошибкой в кабинете. Показывается приглашение войти с возвратом на нужную страницу. Заголовок «Мой кабинет» не остаётся при ошибке обновления сессии.

UUID из `request_id` убран из обычных ошибок полей и гостевого состояния. Для прочих API-сбоев он остаётся внутри закрытого блока **«Данные для поддержки»**. Это помогает искать запрос в логах, не загромождая сообщение пользователю. Трассировки и секреты в этот блок не добавляются.

Кнопка с **N** — индикатор разработки Next.js. В конфигурацию добавлено `devIndicators: false`. Перезапуск dev-сервера обязателен. Это не отключает CSRF, обработку ошибок, логирование или проверки сборки. Production нельзя запускать через `npm run dev`; в проекте уже есть Dockerfile для standalone-сборки с `node server.js`.

В блоке команды вместо наклонённого `th.` используется предоставленный логотип без деформации. Тексты о сервисе, подборе и выборе мест переписаны проще. Сведения о годе работы взяты из вашего сообщения; вымышленные цифры продаж, отзывы и фотографии сотрудников не добавлены.

Вертикальные постеры на карточке и странице мероприятия не обрезаются; обложку события можно раскрыть отдельно. Для отсутствующей или не загрузившейся фотографии остаётся нейтральная фирменная заглушка. Фотографии реальных событий берутся из backend, не из вымышленных карточек.

**Про огромные публичные фото:** API пока не даёт отдельных миниатюр. Разрешение оригинала не меняется; отображение 300-Мп растровой картинки всё ещё может быть тяжёлым для браузера посетителя. Для каталога стоит загружать разумные обложки; отдельные серверные миниатюры — самостоятельная оптимизация, которая здесь не имитируется.

## Проверка после установки

```powershell
npm test
npm run check:source
npm run check:translations
npm run typecheck
npm run lint
npm run test:components
npm run build
```

В браузере проверьте загрузку файла и HTTPS-ссылки для события и черновика схемы, SVG после сохранения, выбор/масштабирование своей арены, обе темы, мобильный экран и гостевую заявку с входом. Настоящие крупные файлы и API-запросы надо проверять с вашей новой версией Django.

Подробный фактический результат: `docs/verification-usability.md`.

## Где менять код

- `src/lib/image-upload.ts`: лимиты, распознавание формата и размеров, payload файла/URL.
- `src/features/staff/image-upload.tsx`: поля, предпросмотр, подтверждение прав, ошибки и конфликт версии.
- `src/features/staff/resource-page.tsx`: обложка при создании и редактировании.
- `src/lib/seat-viewport.ts`: математика камеры, пространственная сетка, размеры точек и Canvas renderer.
- `src/features/seat-map/seat-viewport.tsx`: мышь, touch, колесо, инспектор и масштаб.
- `src/features/seat-map/seat-picker.tsx`: фильтры, список и выбор мест.
- `src/lib/auth-state.ts`, `src/features/auth/session.tsx`, `src/features/auth/login.tsx`: гостевое состояние и inline OTP.
- `src/features/requests/request-form.tsx`: заявка без ранней блокировки входом.
- `src/components/ui/index.tsx`: сообщения об ошибках и reference для поддержки.
- `src/features/catalog/*`, `src/messages/{ru,en}.json`, `src/styles/usability-update.css`: тексты, постеры и оформление.

Для автономного просмотра Canvas-рендера выполните `node scripts/preview-seat-renderer.mjs` и откройте `.test-build/map-preview.html`. Это тестовый стенд, не маршрут сайта. Геометрия и наличие в нём вымышленные и не попадают в production.

# Tickethub: исправление редактора и управления картой

Обновление для `tickethub_frontend_usability_update.zip`. Backend, зависимости, `.env.local`, авторизация, лимиты изображений и адреса API не меняются.

## Установка в Windows / PowerShell

1. Остановите Next.js в терминале сочетанием `Ctrl+C`.
2. Сделайте копию текущей папки фронтенда, особенно если вы меняли исходники после последнего архива.
3. Откройте `tickethub_seatfix_patch.zip`. Скопируйте **содержимое** вложенной папки `tickethub_frontend` в существующую папку фронтенда с заменой файлов. Не создавайте вторую папку `tickethub_frontend` внутри первой.
4. Оставьте свои `.env.local`, `package-lock.json` и `node_modules` на месте. Они не входят в patch.
5. Выполните из папки фронтенда:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev
```

После запуска обновите страницу через `Ctrl+F5`. Новый `npm install` для этого патча не требуется, если зависимости уже установлены. Переключать версии Node.js, удалять базу или выполнять миграции не нужно.

Полный архив `tickethub_frontend_seatfix.zip` содержит весь фронтенд. При распаковке в новую папку перенесите свою `.env.local` и используйте обычный порядок установки зависимостей проекта. Не подменяйте свой рабочий lock-файл случайной новой версией зависимостей.

## Почему карта не двигалась

В `src/features/seat-map/seat-viewport.tsx` обновления камеры объединяются через `requestAnimationFrame`. Cleanup отменял ожидающий кадр, но оставлял его ID в `frame.current`. Следующий setup видел якобы запланированный кадр и не создавал новый. Команды меняли внутренний `cameraRef`, а React-состояние, фон и Canvas оставались неподвижными.

Этот путь возникает при проверочном setup → cleanup → setup эффектов. `reactStrictMode: true` оставлен включённым. Исправлена очистка кадра:

```tsx
useEffect(() => () => {
    if (frame.current !== null) {
        cancelAnimationFrame(frame.current);
        frame.current = null;
    }
}, []);
```

Дополнительно исправлена гонка при быстрой загрузке фонового изображения из кеша: поздний effect больше не сбрасывает его реальные пропорции на 1.6. Пропорции и состояние ошибки привязаны к конкретному URL картинки. Фон и места используют одну камеру.

Нажатие `+` или `−` также активирует управление картой. Потеря захвата указателя завершает жест без случайного выбора места. Обработчики мыши/касания, сохранение выбранных мест, доступность и ограничения масштаба сохранены.

### Как проверить карту

Откройте событие и нажмите «Вся схема». Должна появиться вся арена, а индикатор должен показывать **100%** — это масштаб вписывания, не исходные пиксели фотографии.

Нажмите `+`: меняется не только процент, но и сам фон с местами. Перетащите карту левой кнопкой мыши. Колесо после активации увеличивает область под курсором. Выбор сектора приближает его; «Вся схема» возвращает общий вид. На телефоне сначала включите «Управлять схемой», затем используйте два пальца для масштаба и один для перемещения. «Прокрутка страницы» возвращает обычную прокрутку.

Маленькие точки на общем виде увеличиваются вместе с приближением. Нажатие на достаточно разнесённое место открывает информацию о конкретном секторе, ряде и номере. Недоступное место не становится продаваемым из-за увеличения.

## Почему падал редактор

Раньше `seatDrafts()` вызывал строгий `normalizeSeat()` для каждого места во время создания React-состояния. Если сектор, ряд или номер пустой либо слишком длинный, исключение `INVALID_SEAT_LABEL` обрушивало всю страницу.

По одному стеку невозможно назвать конкретное поле и запись пользовательской схемы. Исправление не угадывает их: оно загружает существующие данные, сохраняет исходные значения и показывает диагностику.

### Новое поведение

* Схема открывается, даже если у отдельных импортированных мест неполные или слишком длинные названия.
* Ничего не удаляется, не обрезается и не перенумеровывается при чтении. Числовая подпись, включая `0`, преобразуется в её строковое представление; отсутствующие подписи не заменяются выдуманными значениями.
* Над редактором появляется блок **«Проверьте данные мест»**. Кнопка **«Показать места с ошибками»** включает фильтр и выбирает первую проблемную запись. Точное объяснение есть в свойствах места.
* Место без корректных координат остаётся в таблице для исправления, но не рисуется в выдуманной точке `(0, 0)`.
* Можно исправить одно место, пока другие остаются неполными. Изменённые и новые места проходят строгую проверку перед отправкой; неизменённые проблемные записи не включаются в запрос.
* Публикация с обнаруженными ошибками блокируется. Защита версии, ограничения пакета, проверка повторов и серверные запреты на изменение опубликованной/используемой схемы остаются.

### Что делать при предупреждении

Нажмите **«Показать места с ошибками»**, проверьте сообщение в свойствах выбранного места, введите правильные данные и нажмите **«Применить на холсте»**. Затем нажмите **«Сохранить изменения»**. Для следующего места снова воспользуйтесь фильтром.

Исправляйте только известные значения: пустой ряд не обязательно означает ряд 1. Если ошибочных записей много, стоит проверить импорт в backend; этот patch делает такие данные доступными для просмотра и исправления, но не восстанавливает неизвестную нумерацию.

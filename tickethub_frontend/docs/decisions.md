# Решения по архитектуре

## Источник истины

Приоритет: приложенный backend-код → его OpenAPI/документация → текущий основной запрос → ранний frontend-ТЗ. Различия не скрываются. UI не переключает вручную PAID/SOLD, не вычисляет server stock и не подменяет approval реальным refund.

## Next App Router и RU/EN

Публичные данные читаются Server Components; Client Components отвечают за интерактивные действия. Общий locale segment `/[locale]`, next-intl и одинаковые ключи словарей. Staff только RU, без копирования двух деревьев страниц. Proxy определяет locale, не полагаясь на IP. Query-параметры сохраняются при смене языка.

## Почему TanStack Query

На клиенте много связанных данных: Hold, availability, заказ, история, ledger, delivery, quote и dashboard. Успешная staff-операция должна инвалидировать соответствующие экраны; вход/выход должен очистить приватный cache; polling прекращается при уходе компонента. Одна небольшая QueryClient-конфигурация решает это проще, чем множество самостоятельных эффектов. Redux/Zustand/GraphQL не добавлены. Query не является авторизацией и не делает финансовые optimistic updates.

## Формы

RHF + Zod использованы для двухшагового входа. Остальные формы имеют понятный React state, native constraints и FieldErrors от Django: не создаётся вторая конкурирующая бизнес-модель. Repeated staff CRUD использует декларативные поля; доменные операции оплаты/выдачи/возврата сделаны отдельными модалками. Непустая форма не очищается при серверной ошибке.

## API и типы

`api/client.ts` — единственная точка browser HTTP, CSRF, request ID, timeout, нормализации ошибок. `api/server.ts` читает публичные данные server-to-server без пользовательской или общей служебной сессии. Типы генерируются из сохранённого OpenAPI; formatter денег один. `unknown` используется для произвольных JSON snapshot/общего CRUD, с проверкой перед применением. Нет `any` для известных DTO.

## Идемпотентность и приватность

В sessionStorage хранятся whitelist выбора, UUID/idempotency key и SHA-256 отпечаток тела, а не email/OTP/пароли/контакты. Hold recovery сохраняет только неперсональный состав предложения. Новый ключ не создаётся при техническом повторе. После неопределённого результата изменённые данные блокируются: безопасность от дублирующих операций важнее автоматического повторного списания. Закрытие финансовой формы не означает отмену запроса на сервере.

## Дизайн

Белый, чёрный, жёлтый из требований; оригинальный логотип без перерисовки. Hero использует настоящую афишу из API; при её отсутствии — нейтральный интерфейсный placeholder, не вымышленное событие. Системный Arial/Helvetica без внешних запросов и без поставки файлов шрифтов. Native dialog, semantic controls и альтернативный список мест. Фактическая доступность/контраст и мобильные размеры требуют проверки, а не декларации.

## Графики и редактор

Для простых рядов аналитики достаточно HTML/CSS полос с текстовыми значениями, поэтому Recharts не добавлен. Геометрия схемы — координаты 0..1. Редактор обновлён: SVG-холст с делегированными указателями, история из 20 локальных операций, diff к серверной версии, запись только через bulk-edit. Block/CSV preview вычисляет сервер. На публичной схеме сохраняются кнопки и альтернативный список; фон необязателен. Это не сотни независимых POST. Это не CAD, не 3D и не редактор билетов.

## Кэш и deployment

Личный кабинет/staff/checkout — no-store и noindex. В этой реализации публичное чтение тоже no-store для простоты согласования; shared CDN-cache не настроен. Same-origin Nginx /api,/ops,/media,/static → Django/его публичные assets; / → Next. Ticket files не должны попадать в public media, но этой подсистемы в текущем backend нет.

## ESLint и проверки

Классические правила hooks и no-explicit-any включены. Compiler-specific purity/set-state-in-effect отключены явно: используются гидратация черновиков/URL, часы и native dialog; React Compiler не настроен. Это не отменяет проверки зависимостей эффектов. Ни конфигурация ESLint, ни AST audit не являются доказательством успешного lint.

## Дополнения API от 7 октября 2026

Новые контракты editor/external-events вынесены из generated.ts: присланный backend помечает OpenAPI как исторический. Контракт проверяется по serializer/action/service, статическим скриптом и unit-перехватом HTTP. Импорт не используется как источник собственного stock. Обложка — отдельный version-checked multipart после Event; серверное read-only поле image не отправляется обычным JSON PATCH. Известный успех создания Event сохраняет его ID до завершения загрузки. Это не заявление о серверной идемпотентности первоначального CRUD POST.

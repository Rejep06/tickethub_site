## Источники и проверка контрактов

Скрипт `check-backend-source.py` читает actual Python AST/исходники без импорта Django. Он проверяет маршруты/actions, поля strict serializers, роль ADMIN, staff password session, multipart/version, bulk limits/locking и возможность публикации без картинки. Это свидетельство соответствия написанного клиента **исходному контракту**, а не доказательство выполнения бизнес-транзакций.

Новые DTO находятся в `src/lib/api/editor.ts` и `external-events.ts`. Присланный backend помечает OpenAPI как исторический, поэтому успешная генерация старых 186 типов не означает актуальность OpenAPI для новых endpoints.

## Проверить перед выкладкой

Сначала зависимости, typecheck/lint/component/build; затем Django check/migrate и реальный вход сотрудника. Прогнать создание/замену фото, валидацию настоящих файлов и 409, отображение после публикации. Прогнать нейтральную схему, блок/CSV, отложенное сохранение, GET после записи, две вкладки, тайм-аут/обновление, опубликованную read-only схему, клонирование. Проверить ADMIN/MANAGER и реальные PARTIAL/FAILED импорта. Затем прежние Hold/Order/staff действия, оба языка, темы, мобильные и клавиатурные сценарии.

На собственном reverse proxy проверить размер multipart и тайм-ауты, не отключая CSRF. Для исходного provider adapter всё ещё требуется отдельная настоящая интеграционная проверка; ограничения подробно зафиксированы самим приложенным backend.

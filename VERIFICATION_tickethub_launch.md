## Новое покрытие

Node: единый путь главной/каталога без фильтра даты, серверный kind, список разрешённых query-параметров, согласие на аналитику по умолчанию off, явное включение/отзыв, отказы localStorage.

Чистый Python: реальная/служебная/выключенная категория, служебные предки, незаполненные шаблоны RU/EN и источник-продавец, сохранение текста без изменений. Эти функции импортируются без Django.

API-тесты, ожидающие запуска в отдельной БД: публикация через endpoint и model validation, публичные выдачи, kind/descendants, TBA+датированные события, category-image multipart и JSON URL, права/роль/CSRF, expected_version, отключение категории с опубликованными событиями и несовместимый тип родителя. В тесте URL используется mock downloader — даже его успешный прогон не будет проверкой внешнего HTTP-скачивания.

Проверки deployment проверяют генерацию разных случайных секретов, 600 на файл, запрет перезаписи, отбрасывание неправильных доменов/поддержку IDN, отсутствие наружных портов у приложений и базы, раздельную тестовую БД, server-only Host и выключенные по умолчанию публичные формы. Это структурные проверки YAML, не вычисленная конфигурация docker compose config.

## Как проверялась вёрстка

Сами TSX-исходники страниц преобразованы в статический HTML небольшим JSX-рендерером с тестовыми адаптерами UI/hooks/Next. CSS взят из проекта; браузер Chromium открыт через Playwright page.set_content. Использованы явно тестовые названия и нейтральные состояния без фотографии. Реальные API и React lifecycle не исполнялись. Изображения со стенда не включены в публичные данные приложения.

Поэтому здесь подтверждается только отсутствие переполнения в проверенных статических состояниях и удаление старой LIVE/YOUR MOMENT композиции. Реальная работа кнопок, формы входа, сохранение фото, переходы и смена темы должны пройти браузерную приёмку после сборки.

## Воспроизведение

Из tickethub_frontend:

```bash
npm test
npm run check:translations
npm run check:source
npm run typecheck
npm run lint
npm run test:components
npm run build
```

Из tickethub_backend/backend (первые команды могут работать без Django):

```bash
python -m unittest events.tests.test_publication_rules -v
python -m compileall -q .
# Ниже нужны зависимости и отдельная тестовая PostgreSQL:
python manage.py makemigrations --check --dry-run
python manage.py test events.tests.test_launch_catalog --noinput
```

Из корня:

```bash
python deploy/tests/test_config.py
# Для всех 12 проверок нужен PyYAML; без него 8 YAML-проверок явно пропускаются.
```

Полный изолированный backend check и production build описаны в DEPLOY_tickethub.md. Не запускайте тесты против рабочей базы и не обходите проваленные проверки.

## Важные ограничения перед релизом

- Миграция намеренно снимает с публикации некорректные импортированные записи. До выполнения нужна резервная копия; после — ручная модерация.
- Демонстрационные записи старой базы не удалены. catalog_audit --strict выявляет опубликованные demo-записи; менеджер снимает их с публикации.
- Фотографии категорий не подставляются из случайных источников; их нужно загрузить с правом использования.
- Миниатюры больших оригиналов не генерируются. Для быстрых карточек используйте отдельные веб-обложки; 300-МП оригиналы не являются оптимальным контентом афиши.
- JSON-снимок frontend API дополнен новыми полями; это не результат запуска генерации живой схемы Django. Дополнение backend API: tickethub_backend/docs/catalog-launch-api.md. После установки зависимостей пересоздайте схему в штатном порядке при необходимости.
- Скрипт Python lock создаёт lock на вашей подключённой машине, не имитирует его в архиве. JavaScript package-lock сохранён из присланного проекта.
- Доставка email, восстановление резервной копии, реальные документы, безопасность окружения и сквозные сценарии остаются условиями открытия сайта посетителям.

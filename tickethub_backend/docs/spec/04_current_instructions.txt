========================================
НЕ ВРАТЬ О ПРОВЕРКАХ
========================================

Очень важное правило.

Никогда не пиши:

«Все тесты прошли»

если они реально не запускались.

Разделяй:

CODED
— код реализован;

STATICALLY CHECKED
— выполнена синтаксическая/статическая проверка;

EXECUTED
— приложение реально запускалось;

TESTED
— тест реально был выполнен;

BLOCKED
— проверка невозможна из-за среды.

В финальном отчёте покажи это явно.

========================================
РЕЗЕРВ
========================================

Резерв действует:

10 минут.

Основной flow:

AVAILABLE
→ CHECKOUT_HELD
→ ORDER_HELD
→ SOLD

Очень важное правило:

10 минут действуют ТОЛЬКО пока пользователь оформляет заказ.

Сценарий:

12:00
пользователь резервирует место.

expires_at = 12:10.

Если до 12:10:

POST /orders/

успешно выполнен,

TicketUnit переходит в:

ORDER_HELD.

После этого:

expires_at CheckoutHold больше НЕ должен освобождать билет.

Место закреплено за заказом.

========================================
ИСТЁКШИЙ HOLD
========================================

Если сейчас:

12:11

а expires_at:

12:10,

hold считается EXPIRED,

даже если management command ещё не запускался.

Любая операция должна проверять время на сервере.

Frontend countdown не является источником истины.

========================================
DEFINITION OF VERIFIED
========================================

Отдельно от CODE COMPLETE:

VERIFIED означает:

[ ] dependencies installed

[ ] PostgreSQL started

[ ] migrations applied from clean database

[ ] makemigrations --check passed

[ ] django check passed

[ ] tests passed

[ ] concurrency test passed on PostgreSQL

[ ] API actually started

[ ] health endpoints responded

[ ] Admin actually opened

[ ] seed_demo actually executed.

Если среда не позволяет это проверить:

backend может иметь статус:

CODE COMPLETE
VERIFICATION BLOCKED

Но НЕ:

FULLY VERIFIED.

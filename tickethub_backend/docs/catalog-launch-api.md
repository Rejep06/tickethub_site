# Изменения API: каталог и публикация, 20.10.2026

Миграция: `events.0004_category_images_publication`. Выполнить после резервной копии.

- `GET /api/v1/categories/` возвращает только активные реальные категории с активными родителями; необязательный `kind=SPORT|CONCERT|OTHER`.
- `GET /api/v1/events/` принимает `kind`; фильтр `category` включает её потомков. Дата не отсекается скрытым фильтром на главной. Статусы и `date_tba` остаются честными.
- Category: `image` (локальный media URL), `version`, `is_placeholder` (read-only).
- `PATCH /api/v1/staff/categories/{id}/` требует `expected_version`. Новая категория: обычный POST без expected_version.
- `POST /api/v1/staff/categories/{id}/image/`: тот же контракт, что изображения мероприятия. Multipart: image, expected_version, rights_source, rights_confirmed. JSON: image_url вместо image. Проверки, лимиты и SSRF-защита общие. Только сессия сотрудника и CSRF.
- StaffEvent: read-only `publication_issues` — словарь ошибок по полям. UI блокирует кнопку, сервер независимо проверяет публикацию через API и Django Admin.
- Нельзя публиковать событие в `external-review`, выключенной/служебной категории, с шаблонными `{name}`/`{city-in}`/`{phone}` или остатками инструкции покупки в PortalBilet. Импорт по-прежнему создаёт черновики для проверки, не угадывает категорию.

Миграция снимает с публикации уже опубликованные события с указанными проблемами и повышает version. Записи, места, билеты, заказы, суммы и файлы не удаляются. Автоматической повторной публикации при откате нет. Отредактируйте категорию и текст, затем опубликуйте из staff. Фотографии категорий загружаются отдельно и не выводятся из обложек случайных событий.

JSON-снимок схемы фронтенда расширен для новых полей. Полную схему необходимо получить из обновлённого Django через drf-spectacular после установки зависимостей; старые YAML-снимки не являются доказательством проверки API.

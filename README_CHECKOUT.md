## Модель работы

Доступные реальные билеты → выбор мест/категории → вход и контакты → резерв → промокод по желанию → «Оформить заказ» → очередь менеджера. Онлайн-платёж не является условием оформления. Заказ получает статус NEW, его билеты закрепляются до обработки менеджером, а не только на время checkout-таймера.

В локальном backend `.env` нужны `PUBLIC_FORMS_ENABLED=true`, `ORDER_INTAKE_ENABLED=true`. На production включите их после настройки SMTP, контактов, утверждённых документов и проверок. `online_payments_enabled=false` — нормальный результат для этой модели. `checkout_status --event <slug>` показывает оставшиеся ограничения и фактический остаток.

Промокоды создаёт администратор в `/ru/staff/promo-codes`. Менеджер видит условия и заказы, но не меняет размер скидки. Коды не создаются автоматически. Применения считаются при создании заказа; возврат/отмена не возвращает квоту. Полностью бесплатные заказы и суммирование с персональным Quote не добавлены.

## Ограничения проверки

Автономные тесты и проверки исходников выполнены. Полные Next.js/React-компоненты, Django/PostgreSQL, миграции на реальной БД, гонки запросов, браузерный checkout и развёртывание на VPS в этой среде не проверены: необходимые зависимости и сервисы недоступны. Не считайте этот архив подтверждённым production-релизом до проверок из руководства. Старые отчёты/manifest сохранены как история предыдущих версий; актуальный отчёт указан выше.
